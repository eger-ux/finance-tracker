5. Архитектурные ограничения

Не вводить сложные паттерны проектирования без необходимости.

Не создавать классы там, где достаточно функций и словарей на текущем этапе.

Не использовать SQLite до соответствующего учебного блока.

Не добавлять ML и LLM-функциональность в v0.1.

Стараться разделять логику проекта на небольшие понятные функции.

6. Правила работы с данными

Использовать только синтетические данные.

Не помещать реальные банковские выписки в репозиторий.

Не публиковать .env и секреты.

Демонстрировать работу проекта на искусственных примерах.

7. Текущая задача

Текущая задача: стартовая настройка репозитория и разбор назначения .env.

Что уже реализовано самостоятельно:

Создан репозиторий, README-заготовка опубликована на GitHub, созданы .gitignore и виртуальное окружение, сделан первый commit.

Какие файлы изменились:

README.md находится на GitHub; локально в рабочей папке он не обнаружен.

.gitignore содержит правила для .env и отдельных папок с данными.

Создана папка .venv.

docs/AI_CONTEXT.md обновлён с согласия пользователя этим итогом.

.env не создавался.

Что осталось:

В .gitignore исключены data/private/ и data/real/, но нет правила для всей папки data/.

Создание .env отложено до появления настройки, которую нужно хранить локально.

Какие новые концепции изучены:

.env может хранить локальные настройки и секреты, но не шифрует их. Исключение файла из Git не заменяет осторожное обращение с секретами.

Какие концепции пока вызывают затруднения:

Затруднения не подтверждены.
